# 从 0.1 迁移到 1.0

1.0 保留 0.1 的主要中文对象模型，但提高工具链、制品和错误边界。迁移时应更新清单与
锁，而不是只替换版本文字。

## 1. 更新工具链和依赖

安装言序 1.1.12 与言包 0.5.0，将消费清单改为：

```toml
[包]
格式 = 2
言序 = ">=1.1.12"

[依赖]
言窗 = { 包 = "yanxu-gui", 版 = "^1.0" }
```

本地路径开发可临时加入`路径`，发布应用应使用正式来源。显式更新锁文件，并确认锁中
的 `yanxu-gui` 版本、目标、ABI、大小和 SHA-256 都已变化到 1.0.0。

## 2. 声明最小权限

```toml
[权限]
图形界面 = true
剪贴板 = false
文件对话框 = false
```

只在实际调用相应能力时开启剪贴板或文件对话框。1.0 不再把图形权限视为这两项权限的
隐式授权。

## 3. 修正无效配置

0.1 中被忽略、截断或延后失败的配置，1.0 可能在创建或设置时直接拒绝：

- 窗口和控件尺寸必须是 1 至 16,384 的有限数，且满足最小/最大关系；
- 网格列数为 1 至 64，间距为 0 至 512，内边距为 0 至 127；
- 水平对齐只接受`左/中/右`，垂直对齐只接受`上/中/下`；
- 非零`伸缩`尚未实现，会返回 `GUI_LAYOUT_FEATURE`；
- 滑块最小值必须小于最大值，当前值位于范围内；进度值为 0 至 1；
- 定时器间隔为 10 至 86,400,000 毫秒；
- 配置字段类型错误不再按默认值处理。

先修复这些输入，再升级生产锁。完整错误见 [ERRORS.md](ERRORS.md)。

## 4. 使用结构化错误

不要判断原生错误消息或直接把 `所误.代码` 与 `GUI_*` 比较。言序 1.1.12 的 ABI v2
源代码是 `NATIVE_V2`；稳定后端码通过公开帮助函数读取：

```yanxu
试 则
    窗口.标题（「新标题」）；
救 所误 则
    定 详情 为 界面.错误详情（所误）；
    若 （详情【「代码」】 等于 「GUI_RESOURCE_CLOSED」）则
        言「窗口已经关闭」；
    终
终
```

## 5. 明确资源生命周期

- 可以调用`布局.关闭()`独立释放布局子树；
- 关闭窗口、布局或应用后，不再使用其任何子句柄；
- 取消定时器后可以读取`已取消`，关闭定时器后任何操作都会返回关闭错误；
- 资源不能传给其他线程或另一个言序事件循环；
- 绑定窗口关闭处理器后，处理器需要调用`窗口.关闭()`或`应用.退出()`。

`应用.调试快照()`可在迁移测试中检查存活应用、窗口、布局、控件和定时器数量。

## 6. 更新事件处理

回调继续使用 `法（事件）：空`。自定义业务数据从`事件.详情()`读取；不要在载荷中依赖
覆盖顶层`类型`或`目标`。高频事件可以合并，业务逻辑不应以收到每个物理鼠标移动或
缩放事件为前提。

## 7. 更新原生制品

1.0 的锁必须指向 ABI v2、当前操作系统与架构的正式制品。不要复制 0.1 动态库并只改
清单版本，也不要跨架构复用。源码开发时重新执行 release 构建和
`scripts/prepare-current.sh`，再更新示例或应用锁。

## 验收清单

- 1.1.12 类型检查通过；
- 应用锁离线验证通过；
- 所有窗口都存在确定的关闭路径；
- 无效配置测试断言稳定 `GUI_*` 代码；
- 剪贴板和文件对话框权限按需开启；
- 目标制品摘要和大小与清单一致；
- 实际目标上的自动关闭窗口冒烟通过。
