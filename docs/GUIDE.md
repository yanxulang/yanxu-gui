# 言窗使用与运行模型

言窗 1.0.0 面向言序 1.1.12。公开 API 全部位于 `src/主.yx`，原生实现只通过
ABI v2 暴露固定宽度值、持久回调和代际资源句柄；应用代码不接触 Rust、egui、
winit 指针或布局。

## 安装与锁

新项目优先由言包生成。`--gui`会加入言窗、图形权限、应用元数据和一个可运行入口：

```sh
yanbao new 我的窗口 --gui
yanbao run --manifest-path 我的窗口
```

既有项目把`yanxu-gui` 1.0.0 作为`^1.0`依赖，最低言序设为 1.1.12，并显式生成
`言序.lock`。锁中必须包含当前目标的 ABI v2 文件、大小和 SHA-256；不要手工复制其他
平台的动态库或改写摘要。

## 最小应用

源码导入清单中的锁定别名，创建应用、窗口和布局，最后进入事件循环：

```yanxu
引「包:言窗」为 界面；
定 应用 为 界面.应用（「示例」）；
定 窗口 为 应用.窗口（{「标题」：「示例」，「宽」：800，「高」：600}）；
定 布局 为 窗口.纵向布局（{「间距」：12，「内边距」：16}）；
布局.文字（「你好，言序 GUI！」）；
法 关闭处理（事件）：空 则
    应用.退出（）；
    归 空；
终
窗口.关闭时（关闭处理）；
窗口.显示（）；
应用.运行（）；
```

完整签名见 [API.md](API.md)，编辑器和工具可读取 `api/api-v1.json`。

## 生命周期

应用、窗口、布局、控件和定时器都是显式资源。推荐按以下顺序管理：

1. 创建应用和所有初始窗口；
2. 在进入事件循环前创建布局、控件、回调和定时器；
3. 绑定窗口关闭处理器，确定调用`窗口.关闭()`或`应用.退出()`；
4. 调用`窗口.显示()`后进入`应用.运行()`；
5. 不再使用已关闭资源或它的任何子句柄。

`布局.关闭()`会释放整棵布局子树。`窗口.关闭()`释放窗口、布局、控件和绑定回调。
`应用.关闭()`释放所有资源；`应用.运行()`返回时也会清空模型。可以在测试中调用
`应用.调试快照()`查看各类存活资源数量。

## 控件、布局与样式

布局包括纵向、横向、网格、层叠和双向滚动；它们可递归嵌套。控件包括文字、
按钮、单行/多行输入、复选/单选、下拉、滑块、进度、图片、列表、分隔线、标签页、
菜单和画布。公共属性涵盖显示、启用、尺寸边界、内容、焦点、工具提示、可访问名称
与描述。控件样式支持字体、字号、前景/背景、边框、圆角、内外边距；应用主题可选
系统、浅色和暗色。

系统回退字体用于中文与扩展 Unicode；文本输入交给 winit/平台 IME。应用不应自行
拼装组合文本事件。

## 事件与线程

点击、双击、变化、焦点、键盘、鼠标、滚轮、窗口关闭/移动/缩放、DPI 和文件拖放
均投递为结构化`事件`对象；公开回调签名是`法（事件）：空`，可读取类型、目标、时间、
坐标、按键、修饰键、鼠标按钮、文字和处理状态。回调由宿主保留；原生线程只把事件深拷贝进有界队列，言序
回调只在创建 VM 的所有者线程执行。高频鼠标移动、窗口尺寸和重绘事件会合并；队列
满时不会无界分配。

定时器使用同一队列。取消定时器、关闭父资源、退出应用或 VM 析构都会恰好释放一次
回调与原生资源。窗口事件循环返回后，言窗立即清空模型，所以调试快照的存活资源数
归零，无需等待进程退出。

自定义事件把业务载荷放在`详情`，后端生成的`类型`和`目标`不会被载荷覆盖：

```yanxu
法 接收状态（事件）：空 则
    定 状态 为 事件.详情（）【「状态」】；
    事件.处理（）；
    归 空；
终

按钮.事件（「状态变化」，接收状态）；
按钮.自定义事件（「状态变化」，{「状态」：「已保存」}）；
```

资源绑定创建它的线程和宿主事件循环。把句柄传给其他线程会返回
`GUI_RESOURCE_THREAD`；在另一个事件循环使用会返回`GUI_RESOURCE_LOOP`。

## 错误处理

ABI v2 的运行时源代码是`NATIVE_V2`，稳定的 GUI 分类由后端提供。始终通过公开帮助
函数读取：

```yanxu
试 则
    定 无效窗口 为 应用.窗口（{「宽」：0，「高」：480}）；
救 所误 则
    定 详情 为 界面.错误详情（所误）；
    若 （详情【「代码」】 等于 「GUI_SIZE_RANGE」）则
        言「窗口宽度无效」；
    终
终
```

错误消息只用于诊断。完整分类、稳定规则和多属性顺序更新边界见
[ERRORS.md](ERRORS.md)。

## 权限

使用 GUI 必须在清单声明 `图形界面 = true`。剪贴板和文件对话框分别需要
`剪贴板 = true`、`文件对话框 = true`；它们不能由图形权限隐式获得。官方言窗后端
可凭图形权限装载，但其他 ABI 扩展仍须单独的 `原生扩展`授权。

```toml
[权限]
图形界面 = true
剪贴板 = false
文件对话框 = false
```

开启权限后，可调用`剪贴板读取/写入`、`打开文件`、`打开多个文件`、`保存文件`和
`选择目录`。对话框返回路径或空值，不读取文件内容；应用仍需按自己的文件权限和输入
策略处理结果。

## 画布与图片

画布接受带 `类型` 字段的命令典：清空、线段、矩形、圆、文字、图片、裁剪和变换。
坐标为逻辑像素，winit/egui 按每窗口 DPI 缩放；图片接受 PNG/JPEG 字节并按 SHA-256
缓存纹理。资源推荐通过 `标准:资源` 从 YXB 读取，Bundle 不依赖源码目录。

图片宽高各不超过 4,096，解码分配上限 96 MiB。单画布最多 16,384 条命令、估算存储
64 MiB。`清空`是会被逐帧重放的绘制命令，不会删除历史命令；持续动画应限制命令列
增长。其他容量建议见 [PERFORMANCE.md](PERFORMANCE.md)。

## 测试

普通公共消费测试不需要进入窗口循环，可以创建模型、设置属性、发送自定义事件、检查
错误与资源快照。GUI 包含原生模块，因此使用字节码运行每份规格：

```sh
for file in tests/*.yx; do
  yanxu 查 "$file"
  yanxu 字节 "$file"
done
```

真实窗口必须另做自动关闭冒烟，避免 CI 挂起：

```sh
yanxu 字节 examples/自动关闭冒烟.yx
```

Linux CI 在虚拟显示中执行；macOS 与 Windows 使用原生托管机。测试项目仍需声明
`图形界面 = true`，但未使用的剪贴板和文件对话框权限可以保持关闭。

## Bundle 与发布

`yanbao build --manifest-path <项目> --release --bundle` 或
`yanxu 编 <项目> --release --bundle` 产生当前目标的标准应用目录：

- macOS：`.app`、Info.plist、ICNS、可签名 Frameworks；
- Windows：GUI 子系统 PE、嵌入 ICO/版本/DPI 清单，安全 DLL 搜索策略；
- Linux：AppDir、Desktop Entry 和 hicolor 多尺寸图标，兼容 Wayland/X11。

Bundle 同时包含 standalone 运行时、YXB、原生库、资源、许可证与逐文件 SHA-256
清单。构建在同级随机暂存目录完成，验证通过后原子替换输出。清单的 `signing` 字段
给出平台签名顺序；签名与公证应在最后一次未签名摘要验证之后完成。

发布包必须在六个原生目标分别构建并核对`yanxu_native_module_v2`导出，再汇总制品
索引。当前平台的开发清单不能冒充完整发布包。平台矩阵与已知限制见仓库根
`COMPATIBILITY.md`。
